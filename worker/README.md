# Приватные уведомления о рекомендациях

Обработчик Cloudflare Pages принимает только код рекомендателя, тип действия
и путь страницы.
Имена, телефоны и текст формы через неё не отправляются. Токен Telegram и
`chat_id` хранятся в Secrets на стороне Cloudflare и никогда не попадают в
GitHub Pages или репозиторий.

Нужны два секрета:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

Публичный адрес обработчика:

`https://portfolio-referrals.pages.dev/`

Он указан в `REFERRAL_ENDPOINT` внутри `assets/js/app.js`. Клиент видит обычное
сообщение без служебного кода, а Максим получает отдельное уведомление от бота с
именем рекомендателя.

При известной метке `utm_content` уведомления приходят о кликах по ссылкам
Telegram, WhatsApp и MAX, а также о нажатии каждой из трёх кнопок после
успешного заполнения формы. Для Александра используется `utm_content=7k2`.
Без известной метки уведомления не отправляются. Яндекс.Метрика для этой
схемы не нужна; данные формы и служебные коды не добавляются в текст обращения.

Событие означает нажатие на сайте, а не отправку сообщения в мессенджере.
Блокировщик или ошибка сети могут помешать уведомлению, но не открытию чата.
Доступ к буферу обмена MAX на отправку уведомления не влияет.

Проверка обработчика без настоящих сообщений в Telegram:

```powershell
node worker/test.mjs
```

После изменения списка событий публикуйте обработчик на существующий проект
`portfolio-referrals` перед обновлением сайта. Публикация сайта на GitHub Pages
сама по себе не обновляет обработчик в Cloudflare.
