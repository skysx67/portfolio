# Портфолио + 3 демо-лендинга

Статический сайт-портфолио Максима Вагина и три демо-лендинга к нему.
Без сборки, без зависимостей, без CDN — чистые HTML/CSS/JS и локальные шрифты.
Открывается двойным кликом по `index.html`, публикуется как есть.

**Живой адрес:** https://skysx67.github.io/portfolio/

## Структура

```
.
├── index.html              портфолио (главная)
├── robots.txt, sitemap.xml
├── assets/
│   ├── css/style.css       стили портфолио
│   ├── js/app.js           меню + сборка сообщения в Telegram
│   ├── fonts/              Oranienbaum, Spectral, JetBrains Mono (woff2)
│   └── img/                скриншоты кейсов, og.png
├── demo/
│   ├── remont/             «Ровно» — ремонт квартир, калькулятор сметы
│   ├── potolki/            «Потолок72» — натяжные потолки, прайс
│   └── design/             «Северова» — дизайн интерьера, квиз на стиль
├── docs/kalkulyator.md     как снимать логику калькулятора с клиента
└── CREDITS.md              откуда фото и шрифты
```

Четвёртый кейс — действующий сайт мебельного производства
[Перфекто](https://skysx67.github.io/perfecto-mebel/), он живёт в отдельном
репозитории и подключён в портфолио внешней ссылкой.

## Четыре разных визуальных языка

Демо специально сделаны непохожими друг на друга — это и есть товар.

| Сайт | Типографика | Палитра | Что показывает |
|---|---|---|---|
| Портфолио | Oranienbaum + Spectral + JetBrains Mono | бумага, чернила, бордо | типографический манифест: линии вместо карточек, прайс-таблица вместо тарифных плиток |
| `demo/remont` | Oswald прописными + PT Sans | бетон, графит, строительный оранжевый | прорабская эстетика, нулевые скругления, калькулятор сметы |
| `demo/potolki` | Unbounded + Onest | тёплый крем, глубокий бирюзовый, охра | прайс-первый лендинг, свои SVG-иконки |
| `demo/design` | Prata + Golos Text | песок, графит, глина | журнальная вёрстка на дидоне, квиз на стиль |

Компании вымышленные, телефоны нерабочие (`00-00-00`), формы показывают
«Спасибо, заявка отправлена» и на этом всё. На каждой демо-странице сверху
висит плашка «Демо-проект» со ссылкой обратно в портфолио, и все они закрыты
от поиска через `<meta name="robots" content="noindex">`.

## Движение при прокрутке

Анимации самодельные, без библиотек: `IntersectionObserver` вешает класс
`rv-in`, всё остальное делает CSS. Разметка — атрибут `data-rv` на блоке:

| Значение | Что делает |
|---|---|
| `up` | проявление с подъёмом |
| `mask` | заголовок выходит из-под маски (`clip-path`) |
| `img` | фото открывается шторкой снизу вверх плюс отъезд из зума |
| `wipe` | горизонтальный сгон слева направо (только «Ровно») |
| `fig` | крупная цифра садится из разрядки (только портфолио) |
| `row` | ничего не прячет, нужен чтобы прочертить линейку у кейса |

`data-rv-stagger` на контейнере расставляет детям `--rv-i` — это лесенка
задержек по 55–100 мс.

Правила, которых стоит держаться, иначе движение начинает выглядеть дёшево:

- **Ничего не пружинит.** Кривая одна на сайт, без `overshoot`.
- **Смещения маленькие** (18–26 px) и **длительности длинные** (0,55–1,1 с).
  Быстрое движение на большое расстояние читается как шаблон.
- **Проигрывается один раз.** При возврате наверх ничего не повторяется.
- **Скорость под характер сайта:** «Ровно» — 0,55 с и резкий сгон,
  «Потолок72» — 0,75 с, «Северова» — 1,1 с и медленные шторки.
- **`prefers-reduced-motion` выключает всё** — это не опция, а требование.

Ещё две вещи из того же набора, обе в `assets/js/app.js`:

- **Кольцо за курсором** — бордовый круг 46 px, догоняет мышь с коэффициентом
  0,13 за кадр. Включается только при `(pointer:fine)` и выключается при
  `prefers-reduced-motion`. Системный курсор не прячем: без него человек
  теряет точку клика. Над окном просмотра кольцо скрывается — события мыши
  уходят в iframe, и оно всё равно замерло бы на его краю.
- **Просмотрщик работ** — кнопка «Пролистать здесь» и клик по скриншоту
  открывают настоящий сайт в рамке поверх страницы: калькулятор считает,
  квиз проходится. Всё живёт на одном домене, поэтому `iframe` работает без
  оговорок. Стрелки ← → и свайп по шапке листают четыре работы, Esc
  закрывает, при закрытии `src` сбрасывается в `about:blank`, чтобы сайт
  не висел в памяти. Если врезка не открылась за 8 секунд — показываем
  подсказку про новую вкладку. Ctrl+клик по скриншоту работает как обычная
  ссылка, и без JS ссылка тоже остаётся рабочей.

Две ловушки, на которые уже наступили:

1. Стартовые состояния включает крошечный скрипт в `<head>` (класс `rv-on`).
   Если вешать класс из основного скрипта, страница успевает моргнуть готовым
   видом. Там же страховка: если основной скрипт не доедет, через 1,2 с всё
   показывается принудительно.
2. **Элемент с `clip-path` имеет нулевую видимую площадь, и наблюдатель его
   не замечает.** Поэтому для `mask`/`img`/`wipe` следим за родителем,
   а класс вешаем на сам элемент.

## Производительность

Замер Lighthouse (mobile) держим на уровне: производительность 95+,
доступность 100, SEO 100, лучшие практики 100.

Что для этого сделано и что нельзя ломать:

- **Шрифты локальные.** Никаких `fonts.googleapis.com` — это было 590 мс
  блокировки рендера. Подмножества `latin` + `cyrillic`, `font-display: swap`,
  критичные начертания в `<link rel="preload">`.
- **Шрифты урезаны по глифам** (`pyftsubset`): 1,06 МБ → 0,56 МБ. Кириллица
  оставлена целиком, латиница сжата до цифр, пунктуации, `₽`, стрелок и `✓`.
  Если будете добавлять начертание — прогоните его тем же способом, иначе
  один файл потянет на 50 КБ вместо 12:

  ```bash
  python -m pip install fonttools brotli
  python -m fontTools.subset шрифт.woff2 --unicodes=U+0400-045F,U+0490-0491,U+2116 \
    --layout-features=kern,liga,tnum --flavor=woff2 --no-hinting --output-file=шрифт.woff2
  ```
- **Картинки в WebP, у каждой лесенка ширин и `sizes`.** Файлы называются
  `имя-<ширина>.webp`; в `srcset` перечислены все варианты. Правило: самый
  крупный вариант должен быть **не меньше двух рендерных ширин** блока —
  иначе на retina-экране фото выглядит мыльным. Мелкие варианты жмём в q82,
  крупные (они уходят только на retina) — в q68–72.
  Где макет режет фото сильно (вертикальный кадр в горизонтальную полосу),
  кадрируем заранее при сборке, а не через `object-fit`: иначе браузер грузит
  килобайты, которые всё равно не покажет.
- **`width`/`height` обязаны совпадать с реальным файлом**, иначе едет
  `aspect-ratio` и прыгает вёрстка.
- **LCP-картинка** каждой страницы идёт с `fetchpriority="high"` и `preload`,
  остальные — `loading="lazy"`.
- **Первый экран анимируем быстро.** Проявление блока, попавшего в LCP,
  напрямую прибавляется к замеру: на портфолио первый экран идёт 0,55 с
  против 0,95 с у остальных.
- **Никаких сторонних скриптов.** Аналитику, если появится, добавлять
  с `defer` и проверять замер заново.

Перезамерить локально:

```bash
npx lighthouse https://skysx67.github.io/portfolio/ --only-categories=performance,seo,accessibility,best-practices --form-factor=mobile --screenEmulation.mobile --view
```

## Локальный запуск

```bash
python -m http.server 5173
```

Дальше `http://localhost:5173`. Браузер любит кэшировать CSS —
если правки не видно, обновляйте страницу с Ctrl+F5.

## Публикация

```bash
git add -A && git commit -m "Правки" && git push
```

GitHub Pages настроен на ветку `main`, папка `/`. Обновляется за 20–30 секунд.
Все пути относительные, поэтому при переезде на свой домен ничего править
не нужно — кроме абсолютных URL в `<link rel="canonical">`, `og:url`,
`og:image` и `sitemap.xml`.

## Что где менять

Личные данные лежат только в `index.html`: имя (4 места), Telegram и телефон
в блоке контактов. Цены — там же, в секции «Сколько это стоит», и продублированы
в `application/ld+json` в `<head>` (schema.org) — менять надо в обоих местах.

Блок про скидку первым трём клиентам помечен комментарием
`<!-- Убрать этот блок, когда наберётся три клиента -->`.

Цены на 2026 год взяты по нижней границе рынка: биржи дают 1 500–10 000 ₽
за визитку и 10 000–30 000 ₽ за лендинг у фрилансеров-новичков.
